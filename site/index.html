Why Location Scout

What Location Scout is

Whether you are buying a home, letting one, investing, building or opening a café, the first question about a place is the same: what is it like around here? The answers are public, but spread across a dozen services.

Location Scout gathers them for one Search Area, draws them on a map, and sums them up in Highlights and scores that use fixed, published rules. It is a web app you run yourself: a React frontend and a small backend that asks each public Data Source on your behalf, keeps answers in memory for a while, and stores nothing about you.

  • Open data

    Public sources, each credited beside what it supplies.

  • Transparent

    Every score shows its inputs, rule and points.

  • Private

    No accounts; Saved Locations stay in your browser.

  • Accessible

    Built to WCAG 2.2 AA, in six themes, light and dark.

How a search works

  1. 1

    You choose a Location

    A postcode, an address found with Nominatim, or a click on the map, and a Search Radius around it.

  2. 2

    It is checked to be in England

    From its postcode's country on postcodes.io, before any Layer loads. Wales and Scotland say so and load nothing.

  3. 3

    Each Layer loads on its own

    The backend asks each Data Source, politely rate-limited and cached. One that fails or takes over 8 seconds says “Unavailable”; the rest still show.

  4. 4

    Fixed rules score it

    Category Scores from 0 to 100, weighed by the Scout Mode into the Location Score, and Highlights, each from one Layer's figures.

  5. 5

    You read, save and compare

    In the Overview or the Dashboard; save it, compare it with others, print a report, or ask for an AI Explanation.

Features

Everything about a place, on one screen

Nine Layers on an interactive map, the figures behind them, and scores you can take apart.

  • Nine Layers on the map

    Crime with its year-on-year trend; planning constraints and applications with the new homes they would bring; amenities; schools with their Ofsted judgements; transport; green space; property sales with price change and EPC ratings; land; and demographics from Census 2021. Dense markers cluster, and every figure is also given as text.

    • Crime
    • Planning
    • Amenities
    • Schools
    • Transport
    • Green space
    • Property
    • Land
    • Demographics

  • Scores you can check, and Scout Modes

    Category Scores such as Safety, Schools and Planning freedom, each from 0 to 100 by a fixed, published rule, and a Location Score that weighs them. Open any score to see each input, the figure measured, the thresholds and the points given. A Scout Mode reweighs them for one question, “Should I buy a home here to let?” or “Could I open a café here?”, or set weights of your own.

  • Highlights

    What you need to know, first: short Concern, Watch and Good statements, each from a fixed rule over one Layer's figures and never from AI. Choose one to see its Layer on the map.

  • A Dashboard of Widgets

    Every figure at full width: the Location Score in an arc, Category Scores as bars, and a card of charts for each Layer. Drag, resize and hide the Widgets on a 12-column Grid.

  • Land Opportunity Finder

    Open land worth investigating, with its area, road distance, flood zone and indicative ownership: company, council, other registered or possibly unregistered, and land sales nearby.

  • Save, compare and print

    Keep Search Areas in your browser, export and import them as JSON, compare 2 to 4 side by side, and print a report or save it as a PDF.

  • AI Explanations, if you want them

    With your own Anthropic API key, an Explain button answers questions about the figures on screen, and only those: any number not among them is flagged. Off without a key.

  • Street View, if you want it

    With your own Google Maps key, look around the Location, or any Feature from its popup. Without one, nothing loads from Google.

  • Accessible, in six themes

    Built to meet WCAG 2.2 AA: a skip link, every map marker a button and “Skip past the map”, labelled landmarks, Highlights shaped as well as coloured, reflow at 400% zoom, and reduced motion respected. Light, dark or your system's mode, in Scout, Ocean, Forest, Heather, Sunset or High contrast, each with its contrast ratios listed in Settings.

Before you start

Requirements

  • Windows, macOS or Linux, with Git. Location Scout runs locally: there is nothing to host.

  • Node 26 or later and pnpm 12 or later, as the repository's package.json requires; older versions are refused.

  • An internet connection. Most data is fetched live from its Data Source for each Search Area.

  • A contact email address, for NOMINATIM_USER_AGENT: Nominatim's usage policy asks every app to say who it is.

  • Optional keys for EPC ratings, AI Explanations, Street View, PlanWire and HM Land Registry's ownership data. Each feature stays off without its key.

  • Optional disk space for pnpm data:prepare's land, schools and demographics data: one council by default, about 6.8 GB to download for all of England.

Windows

# pnpm 12 or later

1 Install the prerequisites

You need Git, Node 26 or later and pnpm 12 or later.

How to install each prerequisite on each system
Windows macOS Linux
Git winget install Git.Git xcode-select --install Your package manager, e.g. sudo apt install git
Node, via fnm winget install Schniz.fnm brew install fnm curl -fsSL https://fnm.vercel.app/install | bash
pnpm iwr https://get.pnpm.io/install.ps1 -useb | iex curl -fsSL https://get.pnpm.io/install.sh | sh -

Then install Node 26 with fnm, and check both versions:

fnm install 26
fnm default 26
node --version   # v26 or later
pnpm --version   # 12 or later

Both minimums are set in package.json (engines and devEngines), and pnpm refuses to run on anything older. CI uses Node 26.12.0 and pnpm 12.11.2. More in Getting started.

2 Clone and install

git clone {{REPO_URL}}.git
cd {{REPO_NAME}}
pnpm install

One install sets up the whole pnpm workspace: the React frontend in apps/web, the Hono backend in apps/api, the shared types and the land data scripts.

3 Create .env

Copy the example file to .env in the repository root. The one file configures the backend, the frontend and the scripts: 

# Windows (PowerShell)
Copy-Item .env.example .env

# macOS, Linux and Git Bash
cp .env.example .env

Only NOMINATIM_USER_AGENT is required: the API refuses to start without it. Nominatim's usage policy asks for your app's name and a contact address, and it is sent to the Overpass API too: 

NOMINATIM_USER_AGENT="my-location-scout (you@example.com)"

Never commit .env. Everything else is optional, and its feature stays off when unset. Every setting is explained in .env.example.

4 Add optional keys

Set any of these in .env to switch on what they are for, then restart pnpm dev:

The optional settings in .env and what each switches on
Setting What it switches on
EPC_API_KEY EPC ratings and price per m² in the Property Layer: the bearer token from your account on the Energy Performance of Buildings Data service, signed in with GOV.UK One Login
ANTHROPIC_API_KEY AI Explanations, with your own key from the Claude Console; ANTHROPIC_MODEL picks the model, claude-sonnet-5-5 unless set
GOOGLE_MAPS_API_KEY Street View: a browser key for Google's Maps JavaScript API, restricted to http://localhost:5173/* and that API
PLANNING_APPLICATIONS_PROVIDER, PLANWIRE_API_KEY Planning Applications come from PlanIt, with no key, unless you choose planwire and give its key
PLANIT_USER_AGENT The User-Agent sent to PlanIt, which asks for a contact email; NOMINATIM_USER_AGENT is sent when it is unset
LAND_REGISTRY_DATA_API_KEY HM Land Registry's CCOD and OCOD downloads in pnpm data:prepare, for the indicative Ownership Categories (skipped when unset)
PORT, API_ORIGIN, SITE_URL Where the backend listens (8787), where the frontend sends /api, and the address link previews, robots.txt and sitemap.xml give; all default to localhost

More in Data sources and attribution, AI Explanations and Street View.

5 Run Location Scout

pnpm dev

This starts the backend on http://localhost:8787 and the frontend on http://localhost:5173, which sends /api requests to the backend through a proxy. Both read .env.

  • Search for a postcode, which goes straight to its Location, or an address, looked up with Nominatim; pick one if several match. Or click anywhere on the map.
  • Choose a Search Radius of 0.25, 0.5 (the default) or 1 mile, and a Scout Mode.
  • Bookmark or share the page's address: it keeps the Location, Search Radius, Scout Mode, your own weights and the Layers you switched off.

Location Scout covers England only: a Location in Wales or Scotland says so, and nothing loads. See Run in Getting started.

6 Prepare land data (optional)

The app works without this step. Only the Land, Schools and Demographics Layers, and the scores that use them, wait for it, each saying to run pnpm data:prepare: 

pnpm data:prepare                      # England-wide datasets + Ashfield land (default)
pnpm data:prepare --area "Mansfield"   # add more councils
pnpm data:prepare --all                # every English council: about 6.8 GB, hours

It downloads council and output area boundaries, Census 2021 and household income, schools and their Ofsted outcomes, and each Land Coverage Area's INSPIRE Index Polygons and OpenStreetMap extracts, and converts them with DuckDB into GeoParquet in the git-ignored data/. Re-run it monthly for new INSPIRE data.

Details in Preparing land data.

7 Run the tests

pnpm test       # unit tests, no network calls
pnpm test:e2e   # Playwright, against a stubbed backend
pnpm smoke      # opt-in: calls each live Data Source once
pnpm bench      # opt-in: times a Search Area against the targets

The end-to-end tests drive Chromium, which Playwright downloads once: 

pnpm --filter @location-scout/web exec playwright install --with-deps chromium

pnpm test:ai is the opt-in check of AI Explanations against recorded inputs. More in Testing.

Accessibility

Last reviewed: October 2026

Conformance status: this website is built to meet the Web Content Accessibility Guidelines (WCAG) 2.2 at Level AA, as the app is.

What we have done

  • Keyboard access — every link, button, tab and dialog works with a keyboard alone, with a clear focus outline that the sticky header never hides. A “Skip to content” link leads the page.
  • Screen readers — one main heading, headings in order and labelled landmarks; every control has a name, every screenshot a description, and copying a command is announced.
  • Colour and contrast — text has at least 4.5:1 contrast with its background, and controls, icons and focus outlines at least 3:1, in both light and dark mode, which follow your device. Windows Contrast Themes are respected.
  • Motion — transitions are short, and smooth scrolling and animation are switched off when your device asks for reduced motion.
  • Zoom and reflow — the page reflows down to 320 pixels wide and when zoomed to 400%, without scrolling sideways.
  • Target sizes — every control is at least 24 by 24 pixels, and buttons at least 44 pixels tall on touch screens.
  • Dialogs — the screenshot viewer and these policies move focus in, keep it there, close on Escape and hand focus back to whatever opened them.
  • Without JavaScript — every part of the page, these policies included, can still be read and reached.

Known limitations

  • The widest tables, such as the prerequisites by system, scroll sideways inside their own frame on narrow screens; the frame takes focus, so the arrow keys scroll it.
  • The screenshots show the app's map, whose tiles are not themed; each has a description of what it shows.
